# 连贯的课堂讲稿

先写整支视频的连续讲稿，再切镜头。镜头是拍摄和配音单元，不能成为孤立知识卡；把标题删掉以后，学生仍应听懂前一句为什么引出后一句。

## 一条学习主线

制作前记录：学生看完能解释什么、需要哪些前置概念、一个贯穿案例、核心知识断言及依据、最容易产生的误解。写进工程 `teaching`，字段见 [教学合同](08-teaching-contract.md)。一个视频围绕一个可说清的目标；需要多个陌生前置概念时分步铺垫或拆片。

默认课堂结构（当前课程要求，可按用户覆盖）：

1. **先点题**：“大家好，我是曦曦，今天我们要学习【知识点】。”具体说明要解决的问题。
2. **再吸引注意**：一个生活情境或疑问，例如“把一份秋游通知交给模型，它怎样写出摘要？”先给出学生可想象的对象，再提出矛盾。这里允许先提出问题；正式解释抽象概念时先下准确定义。
3. **定义、机制、例子**：用普通话解释术语；按因果或操作顺序逐层展开，随时回到同一个案例。必要比喻放在定义后，并说明它映射哪一部分、哪些细节不能照搬。
4. **衔接与回扣**：上一段得到的结果成为下一段的输入。例如“现在我们知道参数从训练中来。那么同学这次发送通知时，还会再训练一遍吗？”不能只用“接下来”“再看”掩盖逻辑跳跃。
5. **回收机制**：“本节课我们学习了【概念】，它就是【一句定义或机制】。”用最初的案例收束，不增加新术语。
6. **告别**：“本节课的学习就到这里了，同学们再见。”

贯穿案例至少在引入、机制解释中段和回收各有明确作用；它不是重复一句口号。人物、文件、任务名称保持一致，指代“它、这个、刚才的”时，前一句应能明确找到对象。教材没有规定“每镜三个句子”，不要机械套同一段式。

## 以教材断言为单位核对

把定义、机制、数值、边界逐条列成 `claims`：`text / sourceId / locator / evidence / treatment`。来源是用户教材或可信一手资料，`evidence`保存相关短句，`locator`给章节、页码或页面段落。教材疑点需查证并说明，不能为了遵从教材而扩大结论；在线来源记录链接和访问日期。

旁白自然讲课，引用位置留在工程与资料中。用户要求原文节选时准确保留，避免“教材写到、导学单写到、原文说”等报幕口吻。定义先准确，再用直白解释帮助理解；少用否定句，必要的边界和纠错可以使用。

## 连贯性审稿

逐镜填写 `teaching.purpose / connectionFromPrevious / caseLink / claimIds`，然后合并成连续讲稿检查：

- 学生在开头能说出学什么、为什么关注吗？
- 每个新词出现时都已解释吗？定义是否比原词更好懂？
- 转场是否回答了上一段自然产生的问题？人物、文件、任务和代词是否明确？
- 开始的案例是否在后续机制中得到新的解释，结尾是否真正回答开头的问题？
- 比喻对应哪些关系，边界是否及时说清？

`quality.py --stage script`只检查缺项、引用和格式，不会判断故事是否好听或知识是否真实。还需从零基础学生视角阅读/试听。无法进行真实听感检查时写待试听，不以术语数量或关键词匹配冒充连贯性通过。

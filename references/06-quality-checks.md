# 技术通过与教学质量分开验收

检查报告必须区分技术链路、教学结构、实际观看与听感。每份记录绑定当前工程指纹、渲染代码、素材内容与实际成片；修改后旧记录过期。不能用像素变动、音量或波形对齐来证明学生听懂了。

## 四道检查

1. **讲稿**：`quality.py --project ... --stage script`检查目标、贯穿案例、知识断言来源、定义边界、转场说明和首尾格式。作者再通读连续文稿，检查代词、因果和例子回扣。来源存在只说明可追溯，事实准确要核对原文。
2. **分镜**：`--stage storyboard`检查真实旁白片段、教学变化和图层引用。正常速度看分镜：对象动作是否解释此刻的机制？定义、数据、关系和案例是否正确对应？仅整图推近、装饰晃动或同一动作循环，应返工。
3. **计时与成片**：`--stage timing`检查声学时间、音频指纹、动画锚点和超过5秒的无有效变化区间；`validate.py --require-audio --delivery`检查真实文件、完整解码、H.264/AAC、响度、SHA、字幕和交付。语义图层标注仍需人工检查，自动活动区间不能当审美/教学分数。
4. **审看与试听**：看整片的对象关系和转场，听实际旁白的连贯、起句、重音、呼吸、变速、漏读、重复和声音身份。可用独立审片者/初学者复述目标、定义和例子关系，指出具体时间点。没有听声能力就明确标“听感待试听”，不能填已通过。

新标准先重做一个完整知识点，作为真实教学用例检验Skill。新样片未确认时，不把27支旧片全部重渲染；只有收到对新标准的继续制作授权才扩展，局部修订可直接继承。当前任务已经要求整套更新时无需重复授权，按同一验收执行。

## 可观察证据

- 逐条断言与教材/一手资料片段核对；抽象概念先定义、逐层解释、案例与边界对应。
- 全文去掉镜头标题后仍通顺；开头先点题，案例在中段和结尾被解释；结尾一句机制总结加约定告别语。
- 各教学节拍可在对应声学时间找到前后状态变化；抽帧看布局，正常播放看流畅度，连续5秒以上静止或循环不能靠装饰补点过关。
- 屏上定义和标签可读、可编辑，无文字遮挡/溢出/错字；无旁白字幕、无讲解员等按profile检查。
- 先试听开场、定义、机制和结尾，再整片试听；声学指标不能替代自然度判断。
- 编辑旁白/表达指令→旧声音失效→生成或导入→校准→画面与SRT更新→保存恢复→重新导出；查看的是新版本。

`review.checks`分别记录 `accuracy / narrative / visual / listening` 的实际证据。只有当前指纹和存在的证据文件可使该项变为通过。`quality.py --stage final --require-reviewed`可用于最终验收；缺证据应保持待复核，不允许修改报告粉饰结果。

## Skill回归

`tests/test_teaching.py`检查旧计时被拒绝、语音表达改变使声音失效、锚点随真实时间移动、装饰/循环不计为教学变化、长静态区间被发现。`tests/run_checks.py --out <隔离目录> --browser --video`检验真实编辑器保存、重载和有声导出；测试音明确不是Serena。`tests/test_setup.py`验证安装保护。报告说明平台与未测项，不把功能测试数量当教学质量。
